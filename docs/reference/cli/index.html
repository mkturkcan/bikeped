    Command line¶

    Every script and module entry point in the repository, with what it does, a usage example and its help text. Run the commands from the repository root: the scripts open config.yaml and camera_calibration.json by relative path.

    Command Purpose
    python decision_testbench.py Evaluate the decision pipeline on the conformance scenarios.
    python run_experiments.py Run every experiment in the paper in sequence.
    python run_height_pitch_sweep.py Monte Carlo sweep over camera height and pitch.
    python crosswalk_analysis.py Performance against road width for one and two cameras.
    python generate_figures.py Write the publication figures.
    python sim_visualizer.py Render schematic scenario videos.
    python -m bikeped.scenarios List, inspect, validate, evaluate, generate and export scenarios.
    python -m bikeped.sim Probe a CARLA server, start one, and render scenarios.
    python calibration/calibrate_fisheye.py Fit the lens model to checkerboard frames.
    python calibration/capture_calibration.py Capture checkerboard frames from a live camera.
    python calibration/compare_fisheye_models.py Fit four projection models and compare their error.
    python tools/eval_models.py Evaluate detector checkpoints and cache per-class AP and AR.
    python tools/latency_report.py Per-step latency statistics from a recorded run.
    python tools/carla_find_crosswalks.py Extract crosswalk geometry from a CARLA map.
    python tools/build_docs.py Build this site.
    python bridge.py Run the live starter-kit bridge (from bridge_starter/).

    Testbench and experiments¶

    decision_testbench.py¶

    Runs the scripted scenarios through the decision pipeline and prints one row of frame counts and rates per scenario. The mode flags are checked in this order, and the first one present decides what runs: --error-map, --compare, --monte-carlo, --latency-sweep, --optimize. With no mode flag, the default configuration runs once over all scenarios.

    python decision_testbench.py --compare                    # every named configuration, with localisation error
python decision_testbench.py --no-bbox-noise --compare    # the same without localisation error
python decision_testbench.py --monte-carlo --mc-trials 50 --failure-model gilbert --burst-length 3
python decision_testbench.py --optimize --w-fn 5 --w-fp 1 --w-lat 2

    --no-bbox-noise applies to the five modes. The plain run without a mode flag never adds localisation error, which is why its totals equal those of --no-bbox-noise --compare for the default configuration. --failure-model and --burst-length are read by --monte-carlo only, and the three --w-* weights by --optimize only.

    usage: decision_testbench.py [-h] [--optimize] [--error-map] [--compare]
                             [--monte-carlo] [--mc-trials MC_TRIALS]
                             [--failure-model {iid,gilbert}]
                             [--burst-length BURST_LENGTH] [--bbox-noise]
                             [--no-bbox-noise] [--w-fn W_FN] [--w-fp W_FP]
                             [--w-lat W_LAT] [--latency-sweep]
                             [--eval-cache EVAL_CACHE]
                             [--eval-model EVAL_MODEL]

Decision Testbench

options:
  -h, --help            show this help message and exit
  --optimize            Optimize decision parameters
  --error-map           Print BBox error analysis
  --compare             Compare pipeline configurations
  --monte-carlo         Run Monte Carlo with stochastic detection failures
  --mc-trials MC_TRIALS
                        Number of Monte Carlo trials (default: 50)
  --failure-model {iid,gilbert}
                        Detection failure model: iid (default) or gilbert
  --burst-length BURST_LENGTH
                        Mean burst length for Gilbert model (default: 3.0
                        frames)
  --bbox-noise          Include fisheye BBox localization error (default: on)
  --no-bbox-noise       Disable fisheye BBox localization error
  --w-fn W_FN           Severity-weighted FN weight (default: 5.0)
  --w-fp W_FP           False positive weight (default: 1.0)
  --w-lat W_LAT         Latency weight (default: 2.0)
  --latency-sweep       Sweep camera latency 0–500 ms and generate figure
  --eval-cache EVAL_CACHE
                        Path to eval_cache.json from eval_models.py
  --eval-model EVAL_MODEL
                        Model name in eval cache to use (default: first)

    run_experiments.py¶

    Calls the testbench once per experiment, then generate_figures.py and sim_visualizer.py --no-display, and stops at the first step that fails. The script's docstring puts the full run at about 45 minutes and the run with --skip-optimizer at about 10.

    python run_experiments.py --skip-optimizer

    usage: run_experiments.py [-h] [--skip-optimizer]

Reproduce all paper experiments

options:
  -h, --help        show this help message and exit
  --skip-optimizer  Skip the optimizer (saves ~30 min)

    run_height_pitch_sweep.py¶

    Takes no flags. It sweeps 13 camera heights (1.5 to 7.5 m) against 10 pitches (0 to -90 degrees) on a 40 ft road with 20 Monte Carlo trials per cell, and writes height_pitch_sweep.json to the current directory. If eval_cache.json is present, its measured recall replaces the flat defaults.

    python run_height_pitch_sweep.py

    crosswalk_analysis.py¶

    Takes no flags. It evaluates the pipeline as a function of road width for one-camera and two-camera deployments and prints the result.

    python crosswalk_analysis.py

    generate_figures.py¶

    Takes no flags. It writes six figures as EPS and PDF into paper/: fig_height_pitch, fig_ar_curve, fig_deployment, fig_pipeline, fig_combined and fig_warning_budget. The height-pitch heatmap needs height_pitch_sweep.json and the recall curve needs eval_cache.json; each is skipped with a message when its input is missing. The script does not create the output directory:

    mkdir -p paper
python generate_figures.py

    Three scripts do not parse arguments

    run_height_pitch_sweep.py, crosswalk_analysis.py and generate_figures.py ignore their command line. Passing --help starts the run.

    sim_visualizer.py¶

    Renders the scenarios as a schematic 3D view through the fisheye model, with the pipeline state drawn on each frame. Each scenario becomes sim_<index>_<name>.mp4 in the current directory. --scenarios takes zero-based indices into the conformance list, and --pipeline takes the name of a testbench configuration.

    $ python sim_visualizer.py --no-display --scenarios 7
Rendering 1 scenarios, single-cam

  Rendering: Fast Approach (1-cam, 6.5s)
    Saved: sim_07_fast_approach.mp4 (196 frames)

Done.

    usage: sim_visualizer.py [-h] [--scenarios SCENARIOS [SCENARIOS ...]]
                         [--fps FPS] [--pipeline PIPELINE] [--two-cam]
                         [--height HEIGHT] [--pitch PITCH] [--errors]
                         [--no-save] [--no-display]

3D fisheye scenario visualizer

options:
  -h, --help            show this help message and exit
  --scenarios SCENARIOS [SCENARIOS ...]
                        Scenario indices (0-indexed)
  --fps FPS
  --pipeline PIPELINE
  --two-cam             Render split-screen two-camera view
  --height HEIGHT       Camera height in meters (default: 5.5)
  --pitch PITCH         Camera pitch in degrees (negative=down, default: auto)
  --errors              Show bbox localization error vectors and save
                        observation data
  --no-save
  --no-display

                            [--max-frames MAX_FRAMES]
                            [--initial-fov INITIAL_FOV] [--fit-distortion]

Fisheye Camera Calibration
==========================

Calibrates the equidistant fisheye model (r = f * theta) used by mqtt_bridge.py.
Standard OpenCV fisheye calibration uses Kannala-Brandt with polynomial distortion
coefficients, which does not fit this 200-degree spherical lens on a 16:9 sensor.

This script uses a custom bundle adjustment that directly fits the equidistant
projection model to checkerboard observations.

Parameters calibrated:
    cx, cy         : optical center in the preprocessed frame (pixels)
    focal_length   : equidistant projection focal length (pixels)
    k1, k2         : optional radial correction terms (r = f*(theta + k1*theta^3 + k2*theta^5))

Usage:
    # From a set of images showing a checkerboard:
    python calibrate_fisheye.py --images calibration_frames/*.jpg

    # From a video (extracts frames at an interval):
    python calibrate_fisheye.py --video calibration.avi --interval 30

    # With a known board size and square dimensions:
    python calibrate_fisheye.py --images *.jpg --board-width 9 --board-height 6 --square-size 0.025

    # Enable radial correction terms for higher accuracy:
    python calibrate_fisheye.py --images *.jpg --fit-distortion

    # Interactive mode: step through a video and press 's' to select frames:
    python calibrate_fisheye.py --video calibration.avi --interactive

    Calibrates the same frames with the equidistant, equisolid, stereographic and orthographic models and reports the RMS reprojection error of each.

    usage: compare_fisheye_models.py [-h] --images IMAGES [IMAGES ...]
                                 [--board-width BOARD_WIDTH]
                                 [--board-height BOARD_HEIGHT]
                                 [--square-size SQUARE_SIZE]
                                 [--pad-size PAD_SIZE] [--crop-size CROP_SIZE]
                                 [--initial-fov INITIAL_FOV] [--output OUTPUT]

Compare fisheye projection models

options:
  -h, --help            show this help message and exit
  --images IMAGES [IMAGES ...]
                        Image paths or glob patterns
  --board-width BOARD_WIDTH
  --board-height BOARD_HEIGHT
  --square-size SQUARE_SIZE
  --pad-size PAD_SIZE
  --crop-size CROP_SIZE
  --initial-fov INITIAL_FOV

Compare fisheye projection models
=================================

Runs calibration with each supported projection model on the same
checkerboard frames and reports RMS reprojection error for each.

Models tested:
    equidistant    r = f * theta
    equisolid      r = 2f * sin(theta/2)
    stereographic  r = 2f * tan(theta/2)
    orthographic   r = f * sin(theta)

Usage:
    python compare_fisheye_models.py --images calibration_frames/frame_*.png
    python compare_fisheye_models.py --images calibration_frames/frame_*.png --board-width 7 --board-height 5

    Tools¶

    tools/eval_models.py¶

    Evaluates YOLO checkpoints on a dataset and caches per-class AP and AR in eval_cache.json, which the testbench reads through --eval-cache.

    python tools/eval_models.py --models yolo11x.pt --data cocoaug.yaml
python decision_testbench.py --compare --eval-cache eval_cache.json

    usage: eval_models.py [-h] [--models MODELS [MODELS ...]] [--data DATA]
                      [--cache CACHE] [--cache-only] [--no-sizes]

Evaluate YOLO models and cache per-class AP/AR

options:
  -h, --help            show this help message and exit
  --models MODELS [MODELS ...]
                        Model paths to evaluate
  --data DATA           Dataset config YAML (default: cocoaug.yaml)
  --cache CACHE         Cache file path (default: eval_cache.json)
  --cache-only          Only print cached results
  --no-sizes            Skip per-size computation (faster)

    tools/latency_report.py¶

    Reads the per-frame latency array written by the bridge and prints statistics per pipeline step. The script reads its arguments by hand: the first argument that does not start with a dash is the path, and --csv is the only flag.

    Argument Default Meaning
    PATH latency_data.npy Latency array to load.
    --csv off Also write the statistics to a .csv file next to the input. 
    python tools/latency_report.py latency_data.npy --csv

    tools/carla_find_crosswalks.py¶

    Connects to a running CARLA server and lists the crosswalks of the current map. crosswalks.json in the repository root was exported with it.

    Flag Default Meaning
    --host localhost Server address.
    --port 2000 Server port.
    --map NAME current map Load this map first.
    --goto N none Move the spectator to crosswalk N.
    --interactive off Mark world points interactively.
    --export PATH none Write the crosswalk data to a JSON file. 
    python tools/carla_find_crosswalks.py --map Town10HD_Opt --export crosswalks.json

    tools/build_docs.py¶

    Builds this site from docs_src/ into docs/ and copies the browser simulator next to it.

    Flag Meaning
    --serve Serve a live preview instead of writing the output directory.
    --open Build, then open the result in the default browser.
    --strict Treat warnings as errors.
    --out DIR Write the site to DIR instead of docs/. 
    python tools/build_docs.py --strict --out /tmp/bikeped-site

    Bridge starter kit¶

    bridge_starter/bridge.py¶

    The live system of the starter kit. Settings live in the USER CONFIG block at the top of the file, and three flags override them for a single run. Run it from inside bridge_starter/.

    Flag Meaning
    --video PATH Read this video file instead of the webcam.
    --no-mqtt Disable MQTT publishing.
    --no-window Run without a display window. 
    cd bridge_starter
python bridge.py --video clip.mp4 --no-mqtt

    See the starter kit.
